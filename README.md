# Synthezavrik — пайплайн сравнительного анализа гена

Берёт ген из набора нуклеотидных последовательностей, ищет в этом же наборе похожие на него последовательности (BLAST), выравнивает найденные участки (MAFFT) и строит филогенетическое дерево (IQ-TREE).

```
входной .txt / .fasta
        │  prepare_dataset.sh  (один раз на файл)
        ▼
candidates.fasta ──► нуклеотидная BLAST-база
        └─ transeq (6 рамок) ──► белковая BLAST-база
        │
        │  run_gene.sh  (на каждый ген)
        ▼
ген ─► blastn
   └─► 6 рамок ─► blastp ─► фильтрация ─► лучшая рамка ─► топ-N хитов
                                     ─► выровненные участки ─► MAFFT ─► IQ-TREE ─► дерево (PNG/ASCII)
   └─► getorf (ORF)
```

Всё это можно запустить одной командой (`run_all.sh`) или через веб-интерфейс (`run_app.sh`).

## Требования

- **Linux** (Ubuntu или Debian). На Windows — через **WSL** (см. ниже). На macOS нет `apt`, поэтому инструменты придётся ставить через conda/bioconda, а `setup.sh` в этом случае не подойдёт.
- Права `sudo`: нужны для установки системных пакетов.
- Оперативная память: WSL по умолчанию получает половину RAM компьютера. Обычно этого хватает (см. [Killed](#mafft-или-iq-tree-завершается-с-killed)).

Устанавливаются автоматически:

| Программа | Зачем |
|---|---|
| NCBI BLAST+ (`blastn`, `blastp`, `makeblastdb`) | поиск похожих последовательностей |
| EMBOSS (`transeq`, `getorf`) | трансляция в 6 рамок, поиск ORF |
| MAFFT | множественное выравнивание |
| IQ-TREE 2 | филогенетическое дерево |
| Python 3 + Biopython, pandas, matplotlib, streamlit | скрипты и веб-интерфейс |

## Установка

### Windows: подготовка WSL

1. В PowerShell **от администратора**:
   ```powershell
   wsl --install -d Ubuntu
   ```
   Перезагрузите компьютер, затем задайте логин и пароль Ubuntu.
2. В VS Code установите расширение **WSL** (Microsoft).
3. Держите проект **внутри Linux** (`~/…`), а не на диске `C:` и тем более не в OneDrive. Через `/mnt/c` всё работает медленнее, а OneDrive начнёт синхронизировать тысячи файлов виртуального окружения и результатов.
   ```bash
   cd ~
   git clone https://github.com/<аккаунт>/Synthezavrik.git
   # или, если проект уже лежит на Windows:
   # cp -r "/mnt/c/Users/<пользователь>/…/Synthezavrik" ~/
   ```
4. Откройте проект в VS Code: **F1 → WSL: Connect to WSL → File → Open Folder → `/home/<пользователь>/Synthezavrik`**. Слева внизу должна появиться плашка **WSL: Ubuntu**.
   Не ставьте VS Code через `snap` внутри Ubuntu: нужен обычный VS Code на Windows с расширением WSL.
5. Чтобы `git push` из WSL использовал учётные данные Windows:
   ```bash
   git config --global credential.helper "/mnt/c/Program\ Files/Git/mingw64/bin/git-credential-manager.exe"
   ```

### Если установлена Anaconda/Miniconda

Отключите окружение `base`, иначе виртуальное окружение соберётся на Python из conda:
```bash
conda deactivate
conda config --set auto_activate_base false   # чтобы base не включалась сама
```

### Установка пайплайна (один раз)

Все команды выполняются из папки со скриптами (в репозитории это `test/`):
```bash
cd ~/Synthezavrik/test
chmod +x *.sh
./setup.sh
```
`setup.sh` ставит системные пакеты (спросит пароль `sudo`), создаёт виртуальное окружение `.venv` с Python-библиотеками и раскладывает каталоги `data/`, `databases/`, `results/`, `logs/`. Повторный запуск безопасен: уже установленное пропускается. `./setup.sh --force` переустанавливает Python-пакеты.

Если появилась ошибка `Could not get lock /var/lib/dpkg/lock-frontend … unattended-upgr`, подождите несколько минут, пока Ubuntu доустановит обновления, и запустите `./setup.sh` снова. Lock-файл **не удаляйте**.

В VS Code выберите интерпретатор: **Ctrl+Shift+P → Python: Select Interpreter → Enter interpreter path → `test/.venv/bin/python`**. После этого пропадут предупреждения о неразрешённых импортах (`streamlit`, `pandas`).

## Формат входного файла

Поддерживаются два формата.

**1. Текст с блоками `raw sequence for <ID>`.** Регистр не важен. Если внутри блока есть строка-заголовок `>`, берётся всё, что после неё. Из блока берутся только строки, состоящие из символов `ACGTN` (и пробелов), остальной текст игнорируется.
```
raw sequence for dmel_FBgn0030912
>dmel_FBgn0030912 любое описание
ATGAAACCCGGGTTT...
AAATTTCCC...
raw sequence for dmel_FBgn0000001
...
```

**2. Обычный FASTA**, если в файле нет блоков `raw sequence for`.

Особенности:
- **Повторяющиеся ID** переименовываются в `ID_dup2`, `ID_dup3`…: BLAST-база с дублями не собирается. В лог выводится предупреждение.
- **Строки с IUPAC-символами** (`R`, `Y`, `K`, `M`…) или с нумерацией в стиле GenBank отбрасываются, и последовательность получится короче. Если в ваших данных такое есть, замените эти символы на `N` заранее.
- **Ген указывается по ID.** Сначала ищется точное совпадение, затем подстрока: `-g FBgn0030912` тоже найдёт `dmel_FBgn0030912`.

## Все способы запуска

### `run_all.sh` — полный цикл

```bash
./run_all.sh <файл> -g ГЕН           [опции]   # один ген
./run_all.sh <файл> --genes genes.txt [опции]  # список генов
./run_all.sh <файл> --all             [опции]  # все гены файла
```

| Опция | Описание |
|---|---|
| `-n, --name ИМЯ` | имя датасета (по умолчанию — имя файла без расширения) |
| `--force` | пересоздать BLAST-базы |
| `--no-zip` | не упаковывать результаты в архив |
| остальные | передаются в `run_gene.sh` (см. [Параметры](#параметры)) |

`run_all.sh` делает следующее:
- запускает `setup.sh`, если окружение ещё не настроено;
- готовит датасет. Если содержимое файла изменилось с прошлого раза (проверяется по SHA-256), базы пересоздаются автоматически;
- прогоняет гены. Ошибка на одном гене не останавливает остальные;
- пишет сводку `results/<датасет>/summary.tsv` и архив `results/<датасет>.zip`.

Код возврата равен `0`, только если все гены обработаны успешно.

Формат `genes.txt`: один ID на строку. Пустые строки и строки, начинающиеся с `#`, пропускаются.

### Пошагово

```bash
# 1. Подготовка датасета (один раз на файл)
./prepare_dataset.sh data/my_data.txt            # датасет "my_data"
./prepare_dataset.sh data/my_data.txt -n run1    # своё имя датасета
./prepare_dataset.sh data/my_data.txt --force    # пересоздать

# 2. Анализ одного гена
./run_gene.sh -d my_data -g dmel_FBgn0030912 -t 4

# 3. Анализ списка генов
./run_batch.sh my_data genes.txt -t 4 --top 30
```

Подготовленный датасет можно использовать сколько угодно раз для разных генов и параметров.

Справка по любому скрипту: `./run_gene.sh --help`.

## Параметры

Параметры анализа принимают `run_gene.sh`, `run_batch.sh` и `run_all.sh`; в веб-интерфейсе они задаются в боковой панели.

| Опция | По умолчанию | Описание |
|---|---|---|
| `-e, --evalue` | `1e-5` | максимальный e-value хита |
| `-t, --threads` | `2` | число потоков (BLAST, MAFFT, IQ-TREE) |
| `--min-pident` | `25` | минимальный % идентичности |
| `--min-qcov` | `0` | минимальное покрытие запроса, %; `0` — не проверять |
| `--min-len` | `30` | минимальная длина выравнивания, а.к. |
| `--top` | `50` | сколько лучших хитов брать в дерево |
| `--max-targets` | `100` | `max_target_seqs` для BLAST |
| `--min-orf` | `90` | минимальная длина ORF для `getorf`, нт |
| `--orf-find` | `3` | режим `-find` для `getorf` (3 — нуклеотиды между старт- и стоп-кодонами) |

Как подбирать параметры:
- **`--min-qcov` по умолчанию выключен.** Гены с интронами и UTR дают трансляцию рамки в тысячи а.к., а гомологи совпадают с ней локальными участками в несколько сотен. Покрытие получается 5–10%, и порог в 50% отсекает почти всё.
- **Если не осталось хитов,** скрипт печатает статистику: сколько хитов отсечено каждым порогом и 10 лучших чужих хитов. Ослабляйте тот порог, который отсекает больше всего, например `-e 1e-3` или `--min-pident 20`. Если чужих хитов 0, у гена в этом наборе нет гомологов.
- **Потоки (`-t`)** заметно ускоряют `blastp` на больших наборах. Ставьте по числу ядер.

## Результаты

```
results/
├── <датасет>.zip                     # архив всего датасета (run_all.sh)
└── <датасет>/
    ├── summary.tsv                   # ген, статус, лучшая рамка, число хитов, есть ли дерево
    └── <ген>/
        ├── <ген>.fasta               # последовательность гена
        ├── <ген>_blastn.tsv          # хиты blastn
        ├── <ген>_6frames.faa         # трансляция гена в 6 рамках
        ├── <ген>_blastp.tsv          # все хиты blastp
        ├── <ген>_blastp.filtered.tsv # после фильтрации
        ├── <ген>_blastp.top50.tsv    # отобранные для дерева
        ├── <ген>_blastp_hit_ids.txt  # их ID
        ├── <ген>_best_frame.txt      # лучшая рамка считывания
        ├── <ген>_msa_input.faa       # вход для MAFFT
        ├── <ген>_alignment.fasta     # множественное выравнивание
        ├── <ген>_orfs.fasta          # найденные ORF
        └── phylogeny/
            ├── <ген>_blastp.treefile # дерево (Newick)
            ├── <ген>_blastp.iqtree   # отчёт IQ-TREE (выбранная модель и др.)
            ├── <ген>_blastp.png      # картинка дерева
            └── <ген>_blastp.ascii.txt
logs/<датасет>_<ген>_<дата>.log       # полный лог каждого запуска
```

Колонки таблиц blastp: `qseqid sseqid pident length qcovs evalue bitscore stitle qstart qend sstart send sseq`. У таблицы blastn — первые 8 колонок.

Имена в дереве:
- запрос — `<ген>_frame<1-3><+|->_<начало>-<конец>`: рамка и участок, вошедший в выравнивание;
- хиты — `<ID>_<рамка 1-6>_<начало>-<конец>`.

Поддержки ветвей на дереве: SH-aLRT / UFBoot (1000 повторов каждая). Обычно ветвь считают надёжной при SH-aLRT ≥ 80 и UFBoot ≥ 95.

## Как работает анализ

### Подготовка (`prepare_dataset.sh`)

1. Входной файл копируется в `data/uploads/` и переводится в `data/processed/<датасет>/candidates.fasta`.
2. `makeblastdb` строит нуклеотидную базу.
3. `transeq -frame 6` переводит каждую последовательность в 6 рамок (ID `X_1`…`X_6`), и из этого строится белковая база.

### Анализ гена (`run_gene.sh`)

1. **Извлечение.** Ген извлекается из `candidates.fasta`.
2. **blastn** по нуклеотидной базе — справочный результат, дальше не используется.
3. **Трансляция.** Ген переводится в 6 рамок (`six_frames.py`).
4. **blastp** всех 6 рамок по белковой базе.
5. **Фильтрация** по e-value, % идентичности, длине и покрытию. Self-хиты (рамки самого гена) исключаются.
6. **Лучшая рамка** — рамка с максимальным bitscore среди чужих хитов. Self-хиты здесь не учитываются, иначе всегда побеждала бы самая длинная рамка без стоп-кодонов.
7. **Отбор хитов:** только хиты лучшей рамки, по одному на последовательность-кандидат (лучший по bitscore), топ-N.
8. **Вход для выравнивания** (`build_msa_input.py`). Из хитов берутся только **выровненные участки**, а не белки целиком: длинные геномные последовательности дают трансляции в миллионы а.к., и MAFFT падает по памяти. Запрос обрезается до области, покрытой хитами. Стоп-кодоны `*` заменяются на `X`.
9. **Выравнивание:** `mafft --auto`.
10. **Дерево:** IQ-TREE с автоподбором модели (`-m MFP`), UFBoot и SH-aLRT. Строится только при ≥ 4 последовательностях.
11. **ORF:** `getorf` ищет ORF в гене.
12. **Отрисовка:** `draw_tree.py` рисует дерево в ASCII и PNG.

## Решение проблем

### `$'\r': command not found` или `bad interpreter`
У скриптов Windows-переносы строк (CRLF). Добавьте `.gitattributes` (см. выше), затем:
```bash
sed -i 's/\r$//' *.sh *.py
```

### `Permission denied` при запуске `./скрипт.sh`
```bash
chmod +x *.sh
```

### `Could not get lock /var/lib/dpkg/lock-frontend`
Ubuntu в фоне ставит обновления. Подождите, пока `pgrep -a unattended` перестанет что-либо выводить, и повторите.

### `Окружение не найдено. Сначала выполните: ./setup.sh`
Не выполнена установка, или она прервалась до создания `.venv`. Запустите `./setup.sh`.

### `IQ-TREE не установился` / `IQ-TREE не найден`
В новых версиях Ubuntu пакет может ставить IQ-TREE 3 с командой `iqtree3`. Проверьте:
```bash
ls /usr/bin | grep -i iqtree
```
Если там `iqtree3`, замените в `common.sh` функцию `find_iqtree`:
```bash
find_iqtree() {
    local c
    for c in iqtree3 iqtree2 iqtree; do
        command -v "$c" >/dev/null 2>&1 && { echo "$c"; return 0; }
    done
    return 1
}
```
Ключи `-B`, `--alrt`, `--prefix` в IQ-TREE 3 работают так же.

### MAFFT или IQ-TREE завершается с `Killed`
Не хватило памяти. Посмотрите в логе строку `Запрос: … хитов: N, длины …`: если участки очень длинные, уменьшите `--top`. Можно дать WSL больше памяти: создайте `C:\Users\<пользователь>\.wslconfig`:
```
[wsl2]
memory=12GB
```
Затем в PowerShell выполните `wsl --shutdown` и откройте терминал заново.

### `После фильтрации не осталось хитов`
Посмотрите статистику, которую скрипт печатает перед ошибкой, и ослабьте соответствующий порог (см. [Параметры](#параметры)).

### `Пропускаю IQ-TREE: нужно ≥ 4 последовательностей`
Нашлось меньше трёх гомологов. Ослабьте пороги (`-e 1e-3`, `--min-pident 20`) или увеличьте `--max-targets`.

### `Датасет '…' не подготовлен`
Сначала выполните `./prepare_dataset.sh <файл>` или используйте `run_all.sh`. Имя датасета — имя файла без расширения (или значение `-n`).

### Результаты не обновились после замены входного файла
`prepare_dataset.sh` не пересоздаёт базы для файла с тем же именем. Используйте `--force` или `run_all.sh`: он сам замечает изменения.

### `code: command not found` в WSL
Откройте проект из VS Code на Windows: **F1 → WSL: Connect to WSL → Open Folder**.

### В VS Code подчёркнуты импорты в `app.py`
Выберите интерпретатор `test/.venv/bin/python` (**Python: Select Interpreter**).
