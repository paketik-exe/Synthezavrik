# Алгоритм определения происхождения гена

Программа `classify_gene.sh` получает на вход ген и по схеме ниже относит его к одному из классов:
**Дупликация**, **Древний ген**, **Иные механизмы** (слияние / перестройка, HGT, одомашнивание TE / из ncRNA), **De novo**, **Неопределённо**.

```
0. Есть белок-кодирующая рамка? ── нет ─────────────────────────────► Неопределённо
1. Есть ли гомологи гена?
   ├─ 1.1 да → путь гомологии (не de novo)
   │   2. Где находятся гомологи?
   │      2.1 в том же геноме ───────────────────────────────────────► Дупликация
   │      2.2 в далёких видах в синтенной позиции ──────────────────► Древний ген
   │      2.3 в далёких видах вне синтении:
   │          2.3.1 мозаичная гомология ─────────────────────────────► Слияние / перестройка
   │          2.3.2 гомолог из другой ветви жизни ───────────────────► HGT
   │                иначе ────────────────────────────────────────────► Неопределённо
   └─ 1.2 нет → кандидат de novo
       3. Есть синтенное некодирующее выравнивание в аутгруппе?
          3.1 да ─────────────────────────────────────────────────────► De novo
          3.2 нет: связь с TE / ncRNA?
              3.2.1 да ───────────────────────────────────────────────► Иное происхождение (TE / ncRNA)
              3.2.2 нет ──────────────────────────────────────────────► Неопределённо
```

**Группы видов** (задаются при запуске):
- **фокальный вид** — вид гена (`dmel`);
- **ingroup** — близкие виды (`dsim,dsec`). Целая рамка у них означает, что ген возник в общем предке, а не опровергает de novo. Поэтому на шаге 1 их ортологи не считаются гомологами;
- **аутгруппа** (outgroup) — далёкие виды (`dyak,dere,dana,dpse,…`).

## Входные данные: что включает каждую ветку

| Ветка алгоритма | Что нужно | Ключ |
|---|---|---|
| 1, 2.1, 2.2, 3 | датасет кандидатов (`prepare_dataset.sh`) | `-d` |
| 2.1, 2.2 (надёжнее) | протеомы видов `<вид>.faa` | `--ref-proteins` |
| 2.2, 2.3, 3 (синтения, некодирующие гомологи) | геномы видов `<вид>.fa` | `--ref-genomes` |
| синтения по фланкам | геном и GFF фокального вида (или координаты) | `--focal-genome`, `--focal-gff` / `--locus` |
| 2.3.2 HGT | белки других ветвей жизни `<группа>.faa` (бактерии, археи, вирусы, грибы, растения) | `--hgt-db` |
| 3.2 | библиотека мобильных элементов; последовательности ncRNA | `--te-db`, `--ncrna-db` |
| уточнение 2.1 / 2.2 | дерево IQ-TREE | `--tree` |

**Где брать данные:**
- геномы, аннотации и протеомы дрозофил — FlyBase или NCBI Genomes;
- белки других ветвей жизни — подмножества RefSeq или UniProt по таксонам;
- мобильные элементы — набор транспозонов FlyBase или Dfam;
- ncRNA — FlyBase или RNAcentral.

Если какой-то файл не задан, соответствующая ветка недоступна. Скрипт пишет об этом в лог, а в отчёт попадает «Неопределённо», а не ложный вывод.

## Сводная таблица порогов

| Шаг | Метрика | Порог | Ключ |
|---|---|---|---|
| 0 | длина ORF | ≥ 30 а.к. | `--min-orf-aa` |
| 1 | e-value белкового хита | ≤ 1e-5 | `-e` |
| 1 | % идентичности белка | ≥ 30 % | `--min-pident` |
| 1 | стоп-кодоны в участке субъекта | 0 | — |
| 1 | покрытие запроса (часть) | ≥ 20 % | `--part-cov` |
| 2.1, 2.2 | покрытие запроса (полноразмерный) | ≥ 50 % | `--min-cov` |
| 2.2, 3 | синтения | хит внутри синтенного окна / тот же ключ гена | `--flank`, `--gene-key-regex` |
| 2.1 / 2.2 | поддержка узла дерева | UFBoot ≥ 95 или SH-aLRT ≥ 80 | `--min-uf`, `--min-alrt` |
| 2.3.1 | части мозаики | ≥ 2 гена, перекрытие ≤ 20 %, вместе ≥ 50 % | `--max-overlap` |
| 2.3.2 | Alien Index | > 0 (≥ 45 — уверенно) | `--min-ai` |
| 3 | идентичность ДНК / покрытие ORF | ≥ 70 % / ≥ 50 % | `--nt-pident`, `--nt-cov` |
| 3.2 | хит TE / ncRNA | e ≤ 1e-10, ≥ 80 %, перекрытие ≥ 50 % ORF или ≥ 50 % элемента | `--te-*` |

Покрытие запроса считается по выровненному участку: `(qend − qstart + 1) / qlen`.

## Шаг 0. Белок-кодирующая рамка (предусловие)

**1. Метрики:** длина самого длинного ORF, его доля в последовательности, цепь.

**2. Значения:** ORF ≥ **30 а.к.**, иначе **Неопределённо**.

**3. Файлы и команды:**
- `getorf -find 1` → `origin/<ген>_orfs_aa.fasta` (белки);
- `getorf -find 3` → `origin/<ген>_orfs_nt.fasta` (нуклеотиды);
- `pick_orf.py` → `origin/<ген>_orf.tsv` (колонки `orf_len_aa`, `orf_frac`, `strand`, `start`, `end`), а также `<ген>_orf.faa` и `<ген>_orf.fna` — запросы для BLAST.

В лабжурнале это п. 21.

**4. Почему:** алгоритм определяет происхождение *белок-кодирующего* гена, поэтому без рамки вопрос не определён. Средняя длина случайной рамки около 20 кодонов (стоп-кодон встречается с вероятностью 3/64), и порог 30 а.к. отсекает самые короткие случайные ORF, сохраняя короткие молодые белки. Если известна настоящая белковая последовательность, её задают через `--protein`: в геномной последовательности с интронами самый длинный ORF — только фрагмент гена.

## Шаг 1. Есть ли гомологи гена?

**1. Метрики** (белок ORF против белков и трансляций):
- e-value, % идентичности (`pident`);
- покрытие запроса;
- стоп-кодоны в участке субъекта (`sseq`);
- вид субъекта.

**2. Значения.** Гомолог — хит, у которого одновременно:
- e ≤ **1e-5**;
- pident ≥ **30 %**;
- **0** стопов;
- покрытие ≥ **20 %**;
- вид не из ingroup и это не сам ген.

Хотя бы один такой хит → **1.1** (путь гомологии), ни одного → **1.2** (кандидат de novo).

Сам ген исключается. В датасете — по ID. В протеоме и геноме фокального вида — по тому же ключу `FBgn` в ID субъекта, а если ключа нет, то по идентичности ≥ 99 % на ≥ 95 % длины (`--self-pident`).

**3. Файлы и команды:**

| Команда | Файл |
|---|---|
| `blastp` ORF против 6-рамочной базы датасета (`-outfmt "6 qseqid sseqid pident length qcovs evalue bitscore qlen slen qstart qend sstart send sseq"`) | `origin/<ген>_cand_prot.tsv` |
| `blastp` против протеомов | `origin/<ген>_refprot_<вид>.tsv` |
| `tblastn` против геномов | `origin/<ген>_prot_refgen_<вид>.tsv` |
| `blastp` против других ветвей жизни | `origin/<ген>_hgt_<группа>.tsv` |

Колонки: 3 `pident`, 6 `evalue`, 7 `bitscore`, 8 `qlen`, 10–11 `qstart/qend`, 14 `sseq`.

В лабжурнале: п. 10 (6-рамочная база), п. 12 (`blastp` → `_blastp.tsv`), п. 13 (фильтр по `pident`, `qcovs`, `evalue`).

**4. Почему:**
- **e ≤ 1e-5** — вероятность найти такое сходство случайно во всей базе меньше 10⁻⁵.
- **pident ≥ 30 %** — выше «сумеречной зоны» (20–30 %), где сходство белков перестаёт надёжно указывать на общее происхождение.
- **Целая рамка (0 стопов)** — субъект действительно *белок-кодирующий*. Сходство с некодирующей ДНК — не «гомолог гена», а возможный предшественник de novo гена: его разбирает шаг 3.
- **Покрытие от 20 %** — достаточно, чтобы засчитать и частичную гомологию: она нужна для мозаики на шаге 2.3.1.

Если у гена есть белковый гомолог вне его линии, ген произошёл от уже существовавшего гена, то есть это не de novo.

## Шаг 2.1. Гомологи в том же геноме → Дупликация

**1. Метрики:**
- хит к *другому* гену фокального вида (паралог): те же e-value, pident, стопы, покрытие;
- если есть и синтенный ортолог у аутгруппы, дополнительно: сестринская группа гена в дереве и поддержка узла, либо сравнение bitscore паралога и ортолога.

**2. Значения:**
- паралог: e ≤ 1e-5, pident ≥ 30 %, **покрытие ≥ 50 %**, рамка цела → **Дупликация**;
- если одновременно есть синтенный ортолог у аутгруппы:
  - в дереве ген надёжно (UFBoot ≥ **95** или SH-aLRT ≥ **80**) группируется с паралогом своего вида, или bitscore паралога больше → **Дупликация**;
  - ген группируется с аутгруппой, или ортолог ближе → **Древний ген** (паралог — более древняя копия).

**3. Файлы и команды:**
- `blastp` → `_cand_prot.tsv`, `_refprot_<фокальный вид>.tsv`: хиты, у которых вид `sseqid` = фокальный;
- `run_gene.sh` (п. 19–20 журнала: `mafft --auto`, `iqtree2 -m MFP -B 1000 --alrt 1000`) → `phylogeny/<ген>_blastp.treefile` (метки узлов `SH-aLRT/UFBoot`) и `.iqtree`.

**4. Почему:**
- **Сигнатура дупликации.** Дупликация оставляет вторую копию гена в том же геноме, поэтому полноразмерный паралог прямо на неё указывает. Покрытие ≥ 50 % отличает копию гена от общего домена.
- **Зачем дерево.** У древнего гена тоже может быть древний паралог. Новая копия ближе к своему «родителю» в своём геноме, чем к ортологу далёкого вида, и в дереве группируется с ним.
- **Пороги поддержки.** UFBoot ≥ 95 и SH-aLRT ≥ 80 — пороги надёжности узла, которые рекомендуют авторы IQ-TREE (Hoang et al., 2018; Guindon et al., 2010).

## Шаг 2.2. Гомологи у далёких видов в синтенной позиции → Древний ген

**1. Метрики:**
- полноразмерный хит с целой рамкой у вида аутгруппы;
- синтения хита.

**2. Значения:**
- e ≤ 1e-5, pident ≥ 30 %, **покрытие ≥ 50 %**, 0 стопов, вид ∈ аутгруппа;
- синтения:
  - **по фланкам:** хит лежит внутри синтенного окна у этого вида. Окно ограничено совпадениями левого и правого фланков гена (по 10 кб) на одном контиге на расстоянии ≤ 3 × (2·фланк + длина гена);
  - **по ключу:** запись датасета с тем же идентификатором гена (`FBgn…`).

Если синтенность проверить нельзя, вывод делается с пометкой «синтения не проверена» (`--require-synteny` это запрещает).

**3. Файлы и команды:**
- `blastp` / `tblastn` → `_cand_prot.tsv`, `_prot_refgen_<вид>.tsv` (`sseqid`, `sstart`, `send`);
- `blastdbcmd -range` извлекает фланки из генома фокального вида → `_flanks.fna`;
- `blastn -task dc-megablast` фланков против генома вида → `_flanks_<вид>.tsv`;
- `synteny.py window` → `origin/synteny_<вид>.tsv` (`contig`, `start`, `end`, `status` = `both` | `left` | `right` | `not_found`);
- координаты гена: `synteny.py locus` по GFF или `--locus`.

**4. Почему:**
- **Почему важна синтения.** Ортолог, то есть тот же ген, унаследованный от общего предка, лежит в том же геномном окружении между теми же соседями. Сходство в синтенной позиции у вида, разошедшегося раньше, означает, что ген уже был у общего предка, и он древний.
- **Сходство вне синтении** может быть паралогом, перенесённой копией или результатом перестройки. Его разбирает шаг 2.3.
- **Целая рамка и покрытие ≥ 50 %** показывают, что у аутгруппы это тот же белок-кодирующий ген, а не фрагмент или некодирующая ДНК.

---

## Шаг 2.3.1. Вне синтении, мозаичная гомология → Слияние / перестройка

**1. Метрики:** частичные хиты (покрытие 20–50 %) к *разным* генам, их координаты на запросе (`qstart`–`qend`), взаимное перекрытие, суммарное покрытие.

**2. Значения:**
- не меньше **2 разных генов**;
- каждая часть: e ≤ 1e-5, pident ≥ 30 %, рамка цела;
- перекрытие любых двух частей ≤ **20 %** меньшей из них;
- вместе части покрывают ≥ **50 %** запроса.

**3. Файлы и команды:** `blastp` / `tblastn` → `_cand_prot.tsv`, `_refprot_*.tsv`, `_prot_refgen_*.tsv` (колонки 2, 10, 11). Список частей с координатами — в `origin_report.md`, раздел 2.3.1.

**4. Почему:** при слиянии генов, перетасовке экзонов и перестройках хромосом ген собирается из кусков разных предковых генов. Поэтому разные его участки гомологичны разным генам, а целиком он не похож ни на один. Малое перекрытие частей исключает ситуацию «два хита к одному домену». Суммарное покрытие ≥ 50 % гарантирует, что мозаика объясняет бо́льшую часть гена.

---

## Шаг 2.3.2. Гомолог из другой ветви жизни → HGT

**1. Метрики:**
- лучший хит в базе других ветвей жизни (бактерии, археи, вирусы…);
- **Alien Index:** AI = ln(e_своя + 1e-200) − ln(e_чужая + 1e-200), где e_своя — лучший e-value среди своей ветви, а e_чужая — среди других ветвей (Gladyshev et al., 2008).

**2. Значения:**
- хит в другой ветви: e ≤ 1e-5, pident ≥ 30 %;
- AI > 0 → **HGT**. При AI ≥ **45** уверенность высокая, при 0 < AI < 45 — низкая;
- нет такого хита или AI ≤ 0 → **Неопределённо**.

**3. Файлы и команды:** `blastp` ORF против `--hgt-db/<группа>.faa` → `origin/<ген>_hgt_<группа>.tsv`. AI считается по колонке `evalue` этого файла и всех белковых таблиц шага 1.

**4. Почему:**
- **Что значит AI > 0.** Гомологи гена, унаследованного по вертикали, ближе всего в собственной ветви жизни. Если сходство с бактерией или вирусом сильнее, чем с любым животным, ген, скорее всего, получен горизонтально.
- **Что значит AI ≥ 45.** Чужой хит лучше своего на ≥ 45 единиц натурального логарифма, то есть e-value меньше примерно в 10¹⁹ раз. Это принятый порог уверенного HGT.
- **Обязательная проверка.** HGT-кандидаты нужно проверять на контаминацию сборки: соседние гены должны быть эукариотическими, у гена должны быть интроны и так далее.

## Шаг 3 / 3.1. Синтенное некодирующее выравнивание в аутгруппе → De novo

**1. Метрики:**
- нуклеотидный хит ORF у вида аутгруппы: e-value, идентичность, покрытие ORF, синтенность;
- рамка в этом участке у аутгруппы: стопы в лучшем белковом хите (`sseq`), его покрытие или полное отсутствие белкового сходства;
- у каких видов ingroup рамка цела (для оценки возраста).

**2. Значения:**
- ДНК: e ≤ 1e-5, идентичность ≥ **70 %**, покрытие ORF ≥ **50 %**, синтенно;
- у аутгруппы **нет** целой рамки: стопов ≥ 1, или покрытие белкового хита < 50 %, или белкового сходства нет → **De novo**;
- уверенность «высокая», если синтения проверена и таких видов ≥ 2; «средняя» — один вид; «низкая» — синтения не проверена.

**3. Файлы и команды:**
- `blastn -task blastn` ORF против датасета → `_cand_nt.tsv` (п. 9 журнала);
- то же против геномов → `_nt_refgen_<вид>.tsv`;
- белковые таблицы шага 1 (`sseq` с `*`);
- `synteny_<вид>.tsv`.

**4. Почему:**
- **Определение de novo.** Ген de novo возник из некодирующей ДНК. Значит, в аутгруппе, разошедшейся до его появления, на том же месте генома (синтения) лежит гомологичная ДНК, но белок с неё не транслируется: рамку прерывают стоп-кодоны или сдвиги. Именно это сочетание и проверяется: ДНК похожа, кодирующей рамки нет. Мутации, «открывшие» рамку в фокальной линии, — момент рождения гена.
- **Зачем синтения.** Без неё похожий участок может оказаться копией из другого места генома.
- **Порог ≥ 70 % на ≥ 50 % длины.** Для видов одного рода это заметно выше уровня случайных локальных выравниваний ДНК (около 50–60 %).
- **Ingroup с целой рамкой** показывает, в каком общем предке появился ген.

---

## Шаг 3.2. Связь с TE / ncRNA → Иное происхождение

**1. Метрики:** хит гена в библиотеке мобильных элементов или ncRNA: e-value, идентичность, перекрытие хита с ORF (% длины ORF), покрытие самого элемента.

**2. Значения:**
- e ≤ **1e-10**, идентичность ≥ **80 %**;
- перекрытие с ORF ≥ **50 %** ORF *или* покрытие элемента ≥ **50 %**;

→ **Иное происхождение** (одомашнивание TE / из ncRNA). Иначе → **Неопределённо**.

**3. Файлы и команды:** `blastn` всей последовательности гена против `--te-db` → `origin/<ген>_te.tsv`, против `--ncrna-db` → `origin/<ген>_ncrna.tsv`. Координаты ORF берутся из `_orf.tsv` (`start`, `end`).

**4. Почему:**
- **TE.** Если ORF почти целиком лежит в мобильном элементе, белок унаследован от транспозазы или другого белка TE: это «одомашнивание». Такой ген не из некодирующей ДНК, но и не дупликация обычного гена.
- **ncRNA.** Если ген совпадает с известной некодирующей РНК, рамка возникла в уже транскрибируемой РНК. Это отдельный путь рождения генов («proto-gene» из lncRNA).
- **Строгие пороги** (1e-10, 80 %) нужны потому, что короткие случайные сходства с повторами очень часты.

---

## Неопределённо

Вывод «Неопределённо» делается, когда:
- нет ORF;
- гомологи есть, но не в своём геноме, не в синтении у аутгруппы, не мозаичны и не из другой ветви жизни;
- гомологов нет, синтенного некодирующего участка нет, и связи с TE/ncRNA нет. Возможные причины:
  - быстрая эволюция за пределами чувствительности BLAST (homology detection failure; Weisman et al., 2020);
  - пробел в сборке генома;
  - не заданы нужные данные.

Честное «не знаю» лучше ложного de novo.

## Онлайн-режим (без скачивания баз)

Ключ `--online` (или `run_all.sh --origin`, или галочка в веб-интерфейсе) заменяет локальные референсы запросами к NCBI:

| Ветка | Онлайн-источник | Команда | Файл |
|---|---|---|---|
| 1, 2.1, 2.2 | `refseq_protein`, фильтр `"Insecta"[Organism]` | `blastp -remote` | `origin/online/prot_scope.tsv` → `_refprot_<вид>.tsv` |
| 2.2 синтения | NCBI Orthologs (сходство + локальная синтения) | API Datasets `gene/id/{id}/orthologs`, `product_report` | `origin/online/orthologs.tsv` |
| 2.3.2 HGT | `refseq_protein`, фильтр Bacteria / Archaea / Viruses / Fungi / Viridiplantae | `blastp -remote` | `prot_hgt.tsv` → `_hgt_other_life.tsv` |
| 3 | `refseq_genomic` выбранных видов | `tblastn -remote`, `blastn -remote` | `genome_prot.tsv`, `genome_nt.tsv` |
| синтения для 3 | фланки гена (E-utilities `efetch`) → `refseq_genomic` | `blastn -remote` | `flanks_hits.tsv` → `synteny_<вид>.tsv` |
| 3.2 ncRNA | `refseq_rna`, `biomol_ncrna[PROP]` | `blastn -remote` | `ncrna.tsv` |
| 3.2 TE | набор транспозонов Bergman lab (GitHub, ~1 МБ, один раз) | локальный `blastn` | `_te.tsv` |

**Как это работает:**
- **Скорость.** Удалённый BLAST идёт от минуты до 10+ минут на каждый поиск, а поисков на ген около шести.
- **Кэш.** Результаты кэшируются в `origin/online/`, повторный запуск берёт их оттуда. Чтобы искать заново, добавьте `--refresh`.
- **Далёкие виды.** В онлайн-режиме «далёкие виды» для белков — все найденные виды, кроме фокального и ingroup. Список `--outgroup` задаёт, в каких геномах искать некодирующие участки и синтению.
- **Ключ API (необязательно).** `export NCBI_API_KEY=…` ускоряет запросы к E-utilities.

## Запуск

```bash
./prepare_dataset.sh data/supplementary_file_unannotated_alignments.txt

# минимально: только датасет (синтения по ключу FBgn)
./classify_gene.sh -d supplementary_file_unannotated_alignments -g dmel_FBgn0030912 \
    --ingroup dsim,dsec --outgroup dyak,dere,dana -t 4

# полная схема
./classify_gene.sh -d supplementary_file_unannotated_alignments -g dmel_FBgn0030912 \
    --ingroup dsim,dsec --outgroup dyak,dere,dana \
    --ref-proteins data/reference/proteins --ref-genomes data/reference/genomes \
    --focal-genome data/reference/genomes_focal/dmel.fa --focal-gff data/reference/annotations/dmel.gff \
    --hgt-db data/reference/hgt --te-db data/reference/te.fa --ncrna-db data/reference/ncrna.fa \
    --tree -t 4

# все гены → results/<датасет>/origin_summary.tsv
./classify_gene.sh -d supplementary_file_unannotated_alignments --all -t 4
```

Геном фокального вида держите в отдельной папке, не в `--ref-genomes`: иначе он будет сравниваться сам с собой как «аутгруппа».

**Результаты:** `results/<датасет>/<ген>/origin/`
- `origin.tsv` — все метрики одной строкой;
- `origin_report.md` — ход решения по узлам схемы со значениями метрик;
- промежуточные таблицы BLAST, ORF и синтении.

## Ограничения

- **Синтения по фланкам** работает для близких видов (внутри рода). Для далёких видов надо сравнивать соседние *гены* (ортологи соседей), а не последовательность фланков.
- **Сдвиги рамки** у аутгруппы распознаются косвенно: по стопам и обрыву белкового хита.
- **Параметры BLAST.** Для очень коротких белков (< 30 а.к.) используется `blastp-short`, но его чувствительность всё равно низкая.
