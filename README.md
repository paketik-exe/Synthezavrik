# Synthezavrik — реконструкция эволюционного происхождения белок-кодирующих генов

Программа получает на вход набор нуклеотидных последовательностей и идентификатор гена. Для этого гена она:
1. ищет гомологи и строит филогенетическое дерево;
2. определяет **происхождение гена** по алгоритму проекта.

Возможные вердикты:

| Вердикт | Узел алгоритма |
|---|---|
| Дупликация | 2.1 — гомолог в том же геноме |
| Древний ген | 2.2 — гомолог у далёких видов в синтенной позиции |
| Иные механизмы: слияние / перестройка | 2.3.1 — мозаичная гомология |
| Иные механизмы: горизонтальный перенос (HGT) | 2.3.2 — гомолог из другой ветви жизни |
| De novo | 3.1 — синтенное некодирующее выравнивание в аутгруппе |
| Иные механизмы: одомашнивание мобильного элемента / из ncRNA | 3.2.1 |
| Неопределённо | 2.3.2 / 3.2.2, либо нет ORF, либо не хватает данных |

Метрики, пороги и обоснование каждого узла описаны в [`test/ALGORITHM.md`](test/ALGORITHM.md).

## Схема работы

```
входной .txt / .fasta
        │  prepare_dataset.sh  (один раз на файл)
        ▼
candidates.fasta ──► нуклеотидная BLAST-база
        └─ transeq (6 рамок) ──► белковая BLAST-база
        │
        │  run_gene.sh  (на каждый ген)
        ▼
ген ─► blastn
   └─► 6 рамок ─► blastp ─► фильтрация ─► лучшая рамка ─► топ-N хитов
                                     ─► выровненные участки ─► MAFFT ─► IQ-TREE ─► дерево (PNG/ASCII)
   └─► getorf (ORF)
        │
        │  classify_gene.sh --online  (на каждый ген; run_all.sh --origin)
        ▼
ORF гена (getorf → pick_orf.py)
   ├─► blastp / blastn по датасету
   ├─► NCBI Gene + Orthologs ─────────────► синтенные ортологи
   ├─► blastp -remote refseq_protein ─────► гомологи у насекомых (паралоги / ортологи)
   ├─► blastp -remote другие ветви жизни ─► Alien Index (HGT)
   ├─► tblastn / blastn -remote refseq_genomic ─► некодирующие гомологи у аутгрупп
   ├─► фланки гена ─► blastn -remote ─────► синтенные окна
   ├─► blastn -remote refseq_rna (ncRNA), blastn по набору TE
   └─► дерево из run_gene.sh (если есть)
        │
        ▼
classify_origin.py ─► вердикт + origin_report.md + origin.tsv
```

## Запуск

Все команды выполняются из папки `test/`. На Windows — в WSL (Ubuntu); проект держите внутри Linux (`~/…`), а не на диске `C:` или в OneDrive.

### 1. Установка (один раз)

```bash
cd ~/Synthezavrik/test
chmod +x *.sh
conda deactivate 2>/dev/null   # если стоит Anaconda: окружение base мешает .venv
./setup.sh                     # спросит пароль sudo
```

`setup.sh` ставит BLAST+, MAFFT, EMBOSS, IQ-TREE и создаёт `.venv` с Python-библиотеками. Если apt занят (`Could not get lock … unattended-upgr`), подождите несколько минут и запустите снова.

В VS Code выберите интерпретатор `test/.venv/bin/python` (**Ctrl+Shift+P → Python: Select Interpreter**).

### 2. Веб-интерфейс (проще всего)

```bash
./run_app.sh
```

Откройте http://localhost:8501 и дальше:
1. Загрузите файл.
2. Выберите ген (один, несколько или все).
3. В боковой панели оставьте галочку **«Определить происхождение»** и проверьте виды ingroup и outgroup.
4. Нажмите **▶ Запустить анализ**.

Остановить сервер — `Ctrl+C`.

### 3. Командная строка

```bash
# всё одной командой: подготовка датасета → дерево → происхождение → сводка → zip
./run_all.sh data/supplementary_file_unannotated_alignments.txt -g dmel_FBgn0030912 --origin -t 4

# несколько генов из файла (по одному ID в строке)
./run_all.sh data/supplementary_file_unannotated_alignments.txt --genes genes.txt --origin -t 4
```

То же самое по шагам:

```bash
./prepare_dataset.sh data/supplementary_file_unannotated_alignments.txt          # один раз на файл
./run_gene.sh -d supplementary_file_unannotated_alignments -g dmel_FBgn0030912 -t 4
./classify_gene.sh -d supplementary_file_unannotated_alignments -g dmel_FBgn0030912 \
    --online --ingroup dsim,dsec --outgroup dyak,dere,dana,dpse,dvir
```

Имя датасета — это имя входного файла без расширения. Справка по любому скрипту: `./<скрипт>.sh --help`.

### Основные параметры

| Ключ | Где | По умолчанию | Смысл |
|---|---|---|---|
| `-t` | все | 2 | число потоков |
| `-e` | `run_gene.sh`, `classify_gene.sh` | 1e-5 | порог e-value |
| `--min-pident` | `run_gene.sh` / `classify_gene.sh` | 25 / 30 | минимальный % идентичности белка |
| `--min-qcov` | `run_gene.sh` | 0 | минимальное покрытие запроса (0 — не проверять) |
| `--top` | `run_gene.sh` | 50 | сколько лучших хитов брать в дерево |
| `--ingroup` | `classify_gene.sh`, `run_all.sh` | dsim,dsec | близкие виды: ортологи у них не мешают выводу de novo |
| `--outgroup` | `classify_gene.sh`, `run_all.sh` | dyak,dere,dana,dpse,dvir | далёкие виды, в геномах которых ищутся некодирующие гомологи и синтения |
| `--refresh` | `classify_gene.sh` | — | повторить онлайн-поиски, не беря их из кэша |

### Время и ограничения

- **Время на ген.** `run_gene.sh` — 1–3 минуты. `classify_gene.sh --online` — 10–40 минут: около шести удалённых поисков на серверах NCBI. Повторный запуск берёт их из кэша и занимает секунды.
- **Объём.** Удалённый BLAST рассчитан на небольшое число запросов. Не запускайте `--all --origin` на сотни генов.
- **Короткие версии ID.** Если в датасете есть ID-префиксы одного гена (`gene1` и `gene10`), скрипты сначала ищут точное совпадение.
- **Если хиты не прошли фильтр,** `run_gene.sh` печатает, сколько хитов отсёк каждый порог. Ослабьте нужный, например `-e 1e-3`.

## Что программа даёт на выходе

Все результаты лежат в `test/results/<датасет>/`.

### Сводки по датасету

| Файл | Содержимое |
|---|---|
| `summary.tsv` | по строке на ген: `gene`, `status` (построено ли дерево), `best_frame`, `n_hits`, `tree`, `origin` (вердикт), `confidence` |
| `origin_summary.tsv` | по строке на ген: `gene`, `verdict`, `confidence`, `reason` |
| `../<датасет>.zip` | архив всех результатов датасета |
| `test/logs/<датасет>_<ген>_<время>.log` | полный лог каждого запуска анализа гена |

### Гомологи и дерево: `<ген>/`

| Файл | Содержимое |
|---|---|
| `<ген>.fasta` | последовательность гена |
| `<ген>_blastn.tsv` | нуклеотидные хиты по датасету |
| `<ген>_6frames.faa` | трансляция гена в 6 рамках |
| `<ген>_blastp.tsv` → `.filtered.tsv` → `.top50.tsv` | белковые хиты: все → прошедшие фильтры → отобранные для дерева |
| `<ген>_best_frame.txt` | лучшая рамка считывания |
| `<ген>_blastp_hit_ids.txt` | ID хитов, вошедших в дерево |
| `<ген>_msa_input.faa` | выровненные участки (запрос + хиты) — вход MAFFT |
| `<ген>_alignment.fasta` | множественное выравнивание |
| `<ген>_orfs.fasta` | открытые рамки считывания гена |
| `phylogeny/<ген>_blastp.treefile` | дерево в формате Newick (поддержки SH-aLRT/UFBoot) |
| `phylogeny/<ген>_blastp.iqtree` | отчёт IQ-TREE: выбранная модель, дерево |
| `phylogeny/<ген>_blastp.png`, `.ascii.txt` | картинка и текстовый вид дерева |

Дерево строится, только если в выравнивании ≥ 4 последовательностей.

### Происхождение гена: `<ген>/origin/`

| Файл | Содержимое |
|---|---|
| `origin_report.md` | **ход решения по узлам алгоритма**: какие метрики, с какими значениями, что выполнено, итог и причина |
| `origin.tsv` | все метрики одной строкой (поля ниже) |
| `<ген>_orf.tsv`, `_orf.faa`, `_orf.fna` | выбранный ORF: длина, цепь, координаты; белок и нуклеотиды |
| `<ген>_cand_prot.tsv`, `_cand_nt.tsv` | хиты ORF по датасету (белок / ДНК) |
| `<ген>_refprot_<вид>.tsv` | белковые гомологи по видам |
| `<ген>_hgt_other_life.tsv` | гомологи в бактериях, археях, вирусах, грибах, растениях |
| `<ген>_prot_refgen_<вид>.tsv`, `_nt_refgen_<вид>.tsv` | хиты в геномах видов (tblastn / blastn) |
| `<ген>_flanks_<вид>.tsv`, `synteny_<вид>.tsv` | хиты фланков гена и синтенное окно у вида |
| `<ген>_ncrna.tsv`, `<ген>_te.tsv` | сходство с ncRNA и мобильными элементами |
| `online/` | кэш онлайн-запросов: `gene_id.txt`, `orthologs.tsv`, `locus.tsv`, `flanks.fna`, сырые таблицы удалённого BLAST |

**Поля `origin.tsv`:**
- **всегда:** `gene`, `focal`, `orf_len_aa`, `n_prot_hits`, `n_homologs`, `ingroup_intact`, `verdict`, `confidence`, `reason`;
- **в зависимости от пройденного пути алгоритма:**
  - `paralogs`, `par_best` — паралоги;
  - `anc_species`, `anc_best` — синтенные гомологи у далёких видов;
  - `mosaic_parts`, `mosaic_cov` — мозаика;
  - `hgt_best`, `alien_index` — HGT;
  - `noncoding_outgroup` — виды с некодирующим гомологом;
  - `te_link`, `ncrna_link` — связь с TE / ncRNA.

### Веб-интерфейс

Для каждого гена веб-интерфейс показывает:
- вердикт, уверенность и причину;
- раскрывающийся «Ход решения» (`origin_report.md`);
- лучшую рамку, число хитов и модель IQ-TREE;
- дерево;
- таблицы хитов blastp/blastn и ORF;
- кнопки скачивания zip по гену и по датасету.

## Используемые инструменты

### Внешние программы

| Инструмент | Что делает в проекте | Где используется |
|---|---|---|
| **BLAST+ `makeblastdb`** | строит BLAST-базы из FASTA | нуклеотидная и белковая базы датасета, база мобильных элементов |
| **BLAST+ `blastn`** | ищет сходство нуклеотидных последовательностей. Режимы `blastn` (чувствительный) и `dc-megablast` (межвидовой) | гомологи ДНК в датасете; некодирующие гомологи в геномах (узел 3); фланки гена (синтения); ncRNA и мобильные элементы (3.2) |
| **BLAST+ `blastp`** | ищет сходство белков. Для белков < 30 а.к. — режим `blastp-short` | гомологи гена (узлы 1, 2.1, 2.2, 2.3); поиск HGT (2.3.2); отбор хитов для дерева |
| **BLAST+ `tblastn`** | белок против ДНК, транслированной в 6 рамках. Показывает, есть ли у гомологичного участка целая рамка (стоп-кодоны `*` в `sseq`) | кодирующий или некодирующий участок в геномах других видов (3.1) |
| **BLAST+ `-remote`** | выполняет поиск на серверах NCBI, без локальных баз; `-entrez_query` ограничивает поиск таксонами | онлайн-режим |
| **EMBOSS `transeq`** | трансляция в 6 рамках | белковая база датасета |
| **EMBOSS `getorf`** | открытые рамки считывания (`-find 1` белки, `-find 3` нуклеотиды) | выбор ORF гена (узел 0) |
| **MAFFT** (`--auto`) | множественное выравнивание белков | выравнивание гена с гомологами |
| **IQ-TREE 2** (`-m MFP -B 1000 --alrt 1000`) | подбор модели замен, филогенетическое дерево, поддержки ветвей UFBoot и SH-aLRT | дерево; спорные случаи «дупликация или древний ген» |

### Онлайн-базы и сервисы NCBI

| Ресурс | Что даёт | Узел алгоритма |
|---|---|---|
| **refseq_protein** (удалённый BLAST, фильтр `"Insecta"[Organism]`) | белковые гомологи и паралоги у насекомых | 1, 2.1, 2.2, 2.3.1 |
| **refseq_protein** (фильтр Bacteria / Archaea / Viruses / Fungi / Viridiplantae) | гомологи в других ветвях жизни → Alien Index | 2.3.2 |
| **refseq_genomic** (фильтр по видам `--outgroup`) | геномы других видов: некодирующие гомологи и синтенные окна по фланкам | 3.1, синтения |
| **refseq_rna** (`biomol_ncrna[PROP]`) | некодирующие РНК фокального вида | 3.2 |
| **E-utilities** (`esearch`, `esummary`, `efetch`) | GeneID по ключу FlyBase (FBgn), координаты гена в геноме, последовательности фланков | синтения |
| **NCBI Datasets API** (`gene/id/{id}/orthologs`, `product_report`) | ортологи NCBI — они рассчитываются по сходству белков и локальной синтении — и их белки | 2.2 (синтенный ортолог); исключение белков самого гена |
| **Набор транспозонов *Drosophila*** (Bergman lab, GitHub, ~1 МБ) | канонические последовательности мобильных элементов | 3.2 |

Онлайн-поиски кэшируются в `origin/online/`. Один удалённый поиск занимает от минуты до 10+ минут, на ген их около шести. Ключ `NCBI_API_KEY` в окружении ускоряет запросы к E-utilities.

### Python-библиотеки

| Библиотека | Зачем |
|---|---|
| **Biopython** | чтение/запись FASTA (`extract_gene.py`, `six_frames.py`, `build_msa_input.py`), чтение и отрисовка дерева (`draw_tree.py`) |
| **matplotlib** | PNG дерева |
| **Streamlit**, **pandas** | веб-интерфейс и таблицы в нём |

### Скрипты проекта (`test/`)

| Скрипт | Назначение |
|---|---|
| `setup.sh` | разовая установка: BLAST+, MAFFT, EMBOSS, IQ-TREE через apt, виртуальное окружение `.venv`, каталоги |
| `common.sh` | общие пути и функции, подключается остальными скриптами |
| `prepare_dataset.sh <файл>` | входной файл → `candidates.fasta` → нуклеотидная и белковая BLAST-базы. Один раз на файл |
| `txt_to_fasta.py` | разбор входного файла: блоки `raw sequence for <ID>` или обычный FASTA; повторяющиеся ID переименовываются |
| `run_gene.sh -d ДАТАСЕТ -g ГЕН` | гомологи и дерево для одного гена (10 шагов: blastn → 6 рамок → blastp → фильтр → лучшая рамка → участки → MAFFT → IQ-TREE → getorf → рисунок) |
| `extract_gene.py` | извлекает запись из FASTA по ID (сначала точное совпадение, затем подстрока) |
| `six_frames.py` | трансляция гена в 6 рамках |
| `build_msa_input.py` | вход для MAFFT только из выровненных участков: хиты лучшей рамки, без гэпов, `*` → `X`. Без этого длинные геномные последовательности переполняют память |
| `draw_tree.py` | дерево в ASCII и PNG |
| `classify_gene.sh -d ДАТАСЕТ -g ГЕН --online` | происхождение гена: ORF, поиски, синтения, TE/ncRNA, классификация |
| `pick_orf.py` | выбирает самый длинный ORF из вывода getorf (или берёт известный белок `--protein`) |
| `ncbi_online.py` | онлайн-доступ к NCBI: GeneID, координаты, фланки, ортологи; раскладывает результаты удалённого BLAST по видам |
| `synteny.py` | координаты гена из GFF; синтенное окно у вида по хитам левого и правого фланка |
| `classify_origin.py` | решающая логика по узлам алгоритма → `origin.tsv`, `origin_report.md` |
| `run_batch.sh ДАТАСЕТ genes.txt` | `run_gene.sh` для списка генов |
| `run_all.sh <файл> -g ГЕН [--origin]` | полный цикл одной командой: подготовка → дерево → происхождение (`--origin` онлайн, `--origin-offline` по локальным базам) → сводка → zip |
| `app.py`, `run_app.sh` | веб-интерфейс (http://localhost:8501): загрузка файла, выбор гена, параметры, кнопка запуска, результаты |

`classify_gene.sh` может работать и без интернета, по локальным файлам: `--ref-proteins`, `--ref-genomes`, `--focal-genome`, `--focal-gff`, `--hgt-db`, `--te-db`, `--ncrna-db`. Список ключей — в `./classify_gene.sh --help`.
