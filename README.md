# Synthezavrik — реконструкция эволюционного происхождения белок-кодирующих генов

Программа получает на вход ген (из файла с последовательностями) и выдаёт:

1. **Его происхождение** — один из классов:

   | Класс | Что значит |
   |---|---|
   | **Дупликация** | у гена есть полноразмерный паралог в том же геноме |
   | **Древний ген** | гомолог с целой рамкой есть у далёких видов в синтенной позиции |
   | **Иные механизмы: слияние / перестройка** | разные части гена гомологичны разным генам |
   | **Иные механизмы: горизонтальный перенос (HGT)** | ближайшие гомологи — в другой ветви жизни (бактерии, вирусы…) |
   | **De novo** | белковых гомологов нет, но у аутгруппы есть синтенный *некодирующий* гомологичный участок |
   | **Иные механизмы: одомашнивание мобильного элемента / из ncRNA** | ORF возник из транспозона или некодирующей РНК |
   | **Неопределённо** | данных недостаточно для вывода |

   К каждому выводу прилагаются **уверенность**, **причина** и **отчёт по этапам алгоритма** со значениями всех метрик.

2. **Филогению гена** — найденные гомологи, их выравнивание и филогенетическое дерево (IQ-TREE).

Работать можно из терминала или через веб-интерфейс. Поиск гомологов у других видов по умолчанию идёт **онлайн** на серверах NCBI, поэтому скачивать геномы не нужно.

## Алгоритм

```
0. Есть белок-кодирующая рамка (ORF ≥ 30 а.к.)? ── нет ──────────────► Неопределённо
1. Есть ли гомологи гена?
   ├─ да → 2. Где находятся гомологи?
   │        2.1 в том же геноме ─────────────────────────────────────► Дупликация
   │        2.2 у далёких видов в синтенной позиции ────────────────► Древний ген
   │        2.3 у далёких видов вне синтении:
   │            2.3.1 мозаичная гомология ───────────────────────────► Слияние / перестройка
   │            2.3.2 гомолог из другой ветви жизни ─────────────────► HGT
   │                  иначе ──────────────────────────────────────────► Неопределённо
   └─ нет → 3. Есть синтенное некодирующее выравнивание у аутгруппы?
            3.1 да ───────────────────────────────────────────────────► De novo
            3.2 нет: есть связь с TE / ncRNA?
                3.2.1 да ─────────────────────────────────────────────► Иное (TE / ncRNA)
                3.2.2 нет ────────────────────────────────────────────► Неопределённо
```

Какие метрики используются на каждом этапе, с какими порогами, в каких файлах они лежат и почему из них следует вывод, подробно описано в **[ALGORITHM.md](test/ALGORITHM.md)**.

Пороги по умолчанию:

| Метрика | Порог |
|---|---|
| белковый гомолог | e ≤ 1e-5, идентичность ≥ 30 %, нет стоп-кодонов в участке |
| полноразмерный гомолог | покрытие гена ≥ 50 % |
| мозаика | ≥ 2 разных гена, каждый покрывает 20–50 %, перекрытие ≤ 20 %, вместе ≥ 50 % |
| HGT | Alien Index > 0 (≥ 45 — уверенно) |
| некодирующий гомолог (de novo) | ДНК ≥ 70 % на ≥ 50 % длины ORF, рамка у аутгруппы не цела |
| TE / ncRNA | e ≤ 1e-10, ≥ 80 %, перекрытие ≥ 50 % ORF |
| поддержка ветви дерева | UFBoot ≥ 95 или SH-aLRT ≥ 80 |

## Установка

Нужен Linux (Ubuntu/Debian). На Windows — **WSL**.

### Windows: WSL

1. В PowerShell **от администратора** выполните `wsl --install -d Ubuntu`, перезагрузитесь и задайте логин и пароль Ubuntu.
2. В VS Code установите расширение **WSL** (Microsoft).
3. Держите проект **внутри Linux** (`~/…`), а не в `/mnt/c` и не в OneDrive: так быстрее, и OneDrive не будет синхронизировать тысячи служебных файлов.
   ```bash
   cd ~ && git clone https://github.com/paketik-exe/Synthezavrik.git
   ```
   GitHub не принимает пароль от аккаунта. Войдите через `gh auth login` (`sudo apt install gh`) или используйте персональный токен вместо пароля.
4. Откройте проект в VS Code: **F1 → WSL: Connect to WSL → Open Folder**.

Если установлена Anaconda, выключите окружение `base`, иначе виртуальное окружение соберётся на Python из conda:
```bash
conda deactivate
conda config --set auto_activate_base false
```

### Установка пайплайна (один раз)

```bash
cd ~/Synthezavrik/test
chmod +x *.sh
./setup.sh
```
`setup.sh`:
- ставит BLAST+, MAFFT, EMBOSS и IQ-TREE через `apt` (спросит пароль `sudo`);
- создаёт окружение `.venv` с Biopython, pandas, matplotlib и streamlit;
- раскладывает каталоги проекта.

Повторный запуск безопасен.

В VS Code выберите интерпретатор: **Ctrl+Shift+P → Python: Select Interpreter → `test/.venv/bin/python`**.

## Быстрый старт

Все команды выполняются из папки `test/`.

### Веб-интерфейс

```bash
./run_app.sh            # затем http://localhost:8501
```
1. Загрузите файл с последовательностями.
2. Выберите ген (несколько или все).
3. В боковой панели оставьте галочку **«Определить происхождение»**, проверьте списки близких и далёких видов.
4. Нажмите **▶ Запустить анализ**.

### Терминал

```bash
# всё сразу: дерево + происхождение (онлайн)
./run_all.sh data/supplementary_file_unannotated_alignments.txt -g dmel_FBgn0030912 --origin -t 4

# только происхождение (датасет уже подготовлен)
./classify_gene.sh -d supplementary_file_unannotated_alignments -g dmel_FBgn0030912 \
    --online --ingroup dsim,dsec --outgroup dyak,dere,dana,dpse,dvir
```

**Время работы.** Филогения одного гена занимает 1–3 минуты. Онлайн-определение происхождения — **10–40 минут** на ген (около 6 удалённых поисков на серверах NCBI). Результаты онлайн-поиска кэшируются, поэтому повторный запуск того же гена занимает секунды.

## Входные данные

**Файл с последовательностями** (`.txt` или FASTA):
```
raw sequence for dmel_FBgn0030912
>dmel_FBgn0030912 любое описание
ATGAAACCCGGGTTT...
raw sequence for dmel_FBgn0000001
...
```
- Блоки `raw sequence for <ID>` разбираются автоматически. Если таких блоков нет, файл читается как обычный FASTA.
- Повторяющиеся ID переименовываются в `ID_dup2`.
- Строки с символами кроме `ACGTN` пропускаются.

**ID гена.** Префикс до `_` — вид (`dmel` = *D. melanogaster*), дальше — идентификатор FlyBase (`FBgn…`). По FBgn программа находит ген в NCBI Gene, получает его координаты и ортологи.

**Группы видов** задаются сокращениями FlyBase:

| Сокращение | Вид | | Сокращение | Вид |
|---|---|---|---|---|
| dsim | *D. simulans* | | dana | *D. ananassae* |
| dsec | *D. sechellia* | | dpse | *D. pseudoobscura* |
| dyak | *D. yakuba* | | dwil | *D. willistoni* |
| dere | *D. erecta* | | dvir | *D. virilis* |

Другие сокращения перечислены в `ncbi_online.py`.

- **ingroup** — близкие виды. Целая рамка у них не опровергает de novo: она лишь показывает, что ген возник в их общем предке.
- **outgroup** — далёкие виды. В их геномах ищутся некодирующие гомологи и синтения.

## Что программа выдаёт

### Сводки по датасету

| Файл | Содержимое |
|---|---|
| `results/<датасет>/summary.tsv` | по строке на ген: `status` (построено ли дерево), `best_frame`, `n_hits`, `tree`, **`origin`**, **`confidence`** |
| `results/<датасет>/origin_summary.tsv` | по строке на ген: вердикт, уверенность, причина |
| `results/<датасет>.zip` | архив всех результатов датасета |
| `logs/<датасет>_<ген>_<время>.log` | полный лог филогенетической части |

### По каждому гену: `results/<датасет>/<ген>/`

**Происхождение — `origin/`**

| Файл | Содержимое |
|---|---|
| **`origin_report.md`** | ход решения по узлам алгоритма: какие метрики, какие значения, что выполнено и что нет, итог и причина |
| **`origin.tsv`** | все метрики одной строкой (см. ниже) |
| `<ген>_orf.tsv`, `_orf.faa`, `_orf.fna` | выбранный ORF: длина, цепь, координаты; белок и нуклеотиды |
| `<ген>_cand_prot.tsv`, `_cand_nt.tsv` | хиты BLAST по самому датасету |
| `<ген>_refprot_<вид>.tsv` | белковые гомологи по видам (`refseq_protein`) |
| `<ген>_prot_refgen_<вид>.tsv`, `_nt_refgen_<вид>.tsv` | хиты в геномах (`tblastn` / `blastn`) |
| `<ген>_hgt_other_life.tsv` | хиты в других ветвях жизни |
| `<ген>_te.tsv`, `_ncrna.tsv` | совпадения с мобильными элементами и ncRNA |
| `synteny_<вид>.tsv` | синтенное окно у вида: контиг, координаты, статус (`both` / `left` / `right` / `not_found`) |
| `online/` | кэш онлайн-поиска: исходные ответы NCBI, `orthologs.tsv` (ортологи NCBI), `gene_id.txt`, `locus.tsv`, `flanks.fna` |

Колонки `origin.tsv`:

| Колонка | Значение |
|---|---|
| `gene`, `focal`, `orf_len_aa` | ген, его вид, длина ORF |
| `n_prot_hits`, `n_homologs` | всего белковых хитов; из них засчитано гомологами |
| `ingroup_intact` | у каких близких видов рамка цела (возраст гена) |
| `paralogs`, `par_best` | число паралогов и лучший из них (этап 2.1) |
| `anc_species`, `anc_best` | далёкие виды с синтенным гомологом и лучший хит (2.2) |
| `mosaic_parts`, `mosaic_cov` | число частей мозаики и их суммарное покрытие (2.3.1) |
| `hgt_best`, `alien_index` | лучший гомолог в другой ветви жизни, Alien Index (2.3.2) |
| `noncoding_outgroup` | виды, у которых участок есть, но рамки нет (3.1) |
| `te_link`, `ncrna_link` | число совпадений с TE / ncRNA (3.2) |
| **`verdict`, `confidence`, `reason`** | итог |

Колонки появляются по мере прохождения алгоритма: если вывод сделан на этапе 2.1, колонок этапа 3 не будет.

**Филогения**

| Файл | Содержимое |
|---|---|
| `<ген>.fasta` | последовательность гена |
| `<ген>_6frames.faa` | трансляция в 6 рамках |
| `<ген>_blastn.tsv`, `_blastp.tsv` | все хиты по датасету |
| `<ген>_blastp.filtered.tsv`, `_blastp.top50.tsv` | после фильтрации и отбора |
| `<ген>_best_frame.txt` | лучшая рамка считывания |
| `<ген>_msa_input.faa`, `_alignment.fasta` | вход MAFFT (только выровненные участки) и выравнивание |
| `<ген>_orfs.fasta` | ORF гена |
| `phylogeny/<ген>_blastp.treefile` | дерево (Newick) с поддержками SH-aLRT/UFBoot |
| `phylogeny/<ген>_blastp.iqtree` | отчёт IQ-TREE (выбранная модель) |
| `phylogeny/<ген>_blastp.png`, `.ascii.txt` | картинка и текстовый вид дерева |

Дерево строится, только если в выравнивании ≥ 4 последовательностей. Для генов без гомологов (типичные de novo) дерева не будет, и это нормально: происхождение всё равно определяется.

### В веб-интерфейсе

На вкладке каждого гена видны:
- происхождение, уверенность и причина;
- раскрывающийся «Ход решения по алгоритму» (`origin_report.md`);
- дерево, таблицы хитов, ORF;
- кнопки скачивания результатов в zip.

Для нескольких генов выводится сводная таблица.

## Скрипты и параметры

| Скрипт | Назначение |
|---|---|
| `run_all.sh` | **полный цикл**: подготовка датасета → филогения → происхождение → сводка → архив |
| `classify_gene.sh` | **происхождение гена** по алгоритму |
| `run_app.sh` | веб-интерфейс |
| `prepare_dataset.sh` | файл → FASTA → BLAST-базы датасета (один раз на файл) |
| `run_gene.sh` | филогения одного гена |
| `run_batch.sh` | филогения списка генов |
| `setup.sh` | установка |

Справка по любому скрипту: `./<скрипт> --help`.

### `run_all.sh`

```bash
./run_all.sh <файл> -g ГЕН | --genes список.txt | --all  [опции]
```

| Опция | Описание |
|---|---|
| `--origin` | определить происхождение онлайн |
| `--origin-offline` | то же по локальным референсам (см. [Онлайн и офлайн](#онлайн-и-офлайн)) |
| `--ingroup a,b` | близкие виды (по умолчанию `dsim,dsec`) |
| `--outgroup a,b` | далёкие виды (по умолчанию `dyak,dere,dana,dpse,dvir`) |
| `-n ИМЯ` | имя датасета (по умолчанию — имя файла) |
| `--force` | пересоздать BLAST-базы (делается и сам, если файл изменился) |
| `--no-zip` | без архива |
| `-t N` | потоки |
| остальное | передаётся в `run_gene.sh` |

### `run_gene.sh` (филогения)

| Опция | По умолчанию | Описание |
|---|---|---|
| `-e` | `1e-5` | e-value |
| `--min-pident` | `25` | % идентичности |
| `--min-qcov` | `0` | покрытие запроса (0 — не проверять: у генов с интронами оно всегда мало) |
| `--min-len` | `30` | длина выравнивания |
| `--top` | `50` | сколько хитов брать в дерево |
| `--max-targets` | `100` | `max_target_seqs` BLAST |
| `--min-orf` | `90` | мин. длина ORF для `getorf` |

### `classify_gene.sh` (происхождение)

```bash
./classify_gene.sh -d ДАТАСЕТ -g ГЕН | --all  [опции]
```

| Опция | Описание |
|---|---|
| `--online` | искать онлайн в NCBI |
| `--ingroup`, `--outgroup` | группы видов |
| `--genome-species a,b` | в каких геномах искать онлайн (по умолчанию = `--outgroup`) |
| `--online-scope ENTREZ` | где искать белковые гомологи (по умолчанию `"Insecta"[Organism]`) |
| `--refresh` | не брать онлайн-результаты из кэша |
| `--protein FILE` | известный белок гена (иначе берётся самый длинный ORF) |
| `--tree` | построить дерево, если его нет (уточняет выбор между «дупликация» и «древний») |
| `--require-synteny` | не засчитывать гомологи, синтению которых проверить нельзя |
| `-e`, `--min-pident`, `--min-cov`, `--part-cov`, `--max-overlap`, `--nt-pident`, `--nt-cov`, `--min-ai`, `--te-*`, `--min-uf`, `--min-alrt` | пороги (см. [Алгоритм](#алгоритм)) |

## Онлайн и офлайн

### Онлайн (по умолчанию: `--origin` / `--online`)

Ничего не скачивается, кроме библиотеки мобильных элементов (~1 МБ, один раз с GitHub).

| Что ищется | Где | Как |
|---|---|---|
| белковые гомологи, паралоги | NCBI `refseq_protein`, насекомые | `blastp -remote` |
| синтенные ортологи | NCBI Orthologs (сходство + локальная синтения) | API NCBI Datasets |
| HGT | `refseq_protein`: бактерии, археи, вирусы, грибы, растения | `blastp -remote` |
| некодирующие гомологи | `refseq_genomic` видов из `--outgroup` | `tblastn` / `blastn -remote` |
| синтенное окно | фланки гена (по 10 кб) в тех же геномах | E-utilities + `blastn -remote` |
| ncRNA | `refseq_rna`, только некодирующие | `blastn -remote` |
| мобильные элементы | набор транспозонов *Drosophila* (Bergman lab) | локальный `blastn` |

**Ограничения:**
- **Объём.** Удалённый BLAST NCBI рассчитан на небольшое число запросов. Для нескольких генов он подходит, а прогонять онлайн все гены файла (`--all --origin`) не стоит: это займёт сутки, и NCBI может ограничить доступ.
- **Ключ API.** Регистрация на NCBI и `export NCBI_API_KEY=…` ускоряют запросы к E-utilities.

### Офлайн (`--origin-offline` / `--use-references`)

Подходит для анализа многих генов, но требует ~2 ГБ данных. Положите файлы в `test/data/reference/`:
```
focal/dmel.fa                  геном D. melanogaster
annotations/dmel.genes.gff     строки gene из GFF (FlyBase или NCBI)
proteins/<вид>.faa             протеомы видов
genomes/<вид>.fa               геномы других видов
hgt/<группа>.faa               белки других ветвей жизни
te.fa, ncrna.fa                мобильные элементы, ncRNA
```
Источники: NCBI Datasets (`datasets download genome taxon "<вид>" --reference --include genome,protein,gff3`), UniProt Swiss-Prot по таксономическим разделам. FlyBase из некоторых сетей недоступен.

## Решение проблем

| Симптом | Причина и решение |
|---|---|
| `Permission denied` при `./скрипт.sh` | у скачанного файла нет права на запуск — выполните `chmod +x *.sh` |
| `$'\r': command not found` | Windows-переносы строк — `sed -i 's/\r$//' *.sh *.py` и `.gitattributes` |
| `Нет файла … — положите его рядом с classify_gene.sh` | не хватает скрипта — распакуйте полный набор скриптов в `test/` |
| `Could not get lock /var/lib/dpkg/lock-frontend` | Ubuntu ставит обновления — подождите, пока `pgrep -a unattended` станет пустым |
| `IQ-TREE не найден` | возможно, установлен IQ-TREE 3 (`iqtree3`) — добавьте его в `find_iqtree` в `common.sh` |
| `Killed` в MAFFT/IQ-TREE | мало памяти — уменьшите `--top` или задайте `memory=` в `C:\Users\<вы>\.wslconfig`, затем `wsl --shutdown` |
| `После фильтрации не осталось хитов` | смотрите статистику перед ошибкой и ослабьте порог; если чужих хитов 0, у гена нет гомологов в датасете (для de novo нормально) |
| `Пропускаю IQ-TREE: нужно ≥ 4 последовательностей` | мало гомологов — дерева не будет, происхождение определится |
| `ОШИБКА сети` / `удалённый поиск не удался` | NCBI недоступен или перегружен — повторите позже, удачные поиски возьмутся из кэша |
| онлайн-поиск идёт очень долго | это нормально (минуты на поиск); прогресс виден в логе, результаты кэшируются |
| `ген не найден в NCBI Gene` | ID без FBgn или ген не аннотирован в NCBI — не будет ортологов и синтении по фланкам, вывод получится с пониженной уверенностью |
| вердикт «Неопределённо» | откройте `origin_report.md`: там видно, на каком этапе и почему не хватило данных |
| `TLS handshake failure` при обращении к FlyBase | FlyBase недоступен из вашей сети — используйте онлайн-режим (NCBI) |
| `Invalid username or token` при `git clone` | GitHub не принимает пароль — `gh auth login` или токен |
